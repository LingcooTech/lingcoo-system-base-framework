# 元数据、统一搜索与数据交换

这组能力解决每个行业系统都会重复遇到的数据组织和管理问题，但不定义课程、商品、文章或客户。

## 数据字典

数据字典用于状态、类型和选项等稳定枚举。定义包含稳定 `code`、显示名称和
`string / number / boolean / json` 值类型；条目写入时必须通过对应类型校验。字典产生条目后不能修改
值类型，条目停用而不物理删除，以保留历史引用。领域表应保存条目代码，而不是会变化的显示名称。

## 分类法与标签

`category` 分类法可以选择层级模式，`tag` 始终保持扁平。词条父级必须属于同一分类法，服务层阻止
自引用和后代循环。`resource_terms` 使用 `resource_type + resource_id` 把任意领域资源关联到词条；
领域模块仍须负责确认自己的资源确实存在。

## 统一搜索

Search Provider 声明来源代码、显示名称、所需权限和查询实现。聚合服务只执行当前账号有权使用的
Provider，并按来源分组返回轻量结果，不建立一张复制所有业务内容的“万能搜索表”。领域模块在注册时
可通过 `app.searchRegistry.register(...)` 增加自己的搜索源。管理后台使用 `⌘ K` 或 `Ctrl K` 打开入口。

## 数据交换

Dataset Adapter 声明数据集代码、版本化导出、预检和应用逻辑。基础层内置
`metadata.dictionaries` 与 `metadata.taxonomies` 两个 JSON 数据集。导入分为两步：预检只解析结构、
类型、重复代码和父级引用；只有预检通过后才能在单个数据库事务内 Upsert。每次导出、导入成功或失败
都会写入 `data_exchange_runs`，实际应用同时写入统一审计。

领域模块可通过 `app.datasetRegistry.register(...)` 注册自己的适配器。CSV、XLSX 和大体量异步导入可以
在具体适配器中扩展，但必须保留版本、预检、原子性或明确的分批恢复策略，并禁止在快照中输出凭据、
密码、令牌和其他敏感字段。
